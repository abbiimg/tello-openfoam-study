# Reproducing the source and completed CPU evidence

This addendum provides exact source and observations for the dated managed2.3 experiment. Offline field comparison does not require a GPU, SDK, compiled OpenFOAM library or CFD run. NumPy1.26.4 was used for the recorded mechanical analysis. No fresh-host build or new runtime was performed while curating this bundle.

1. Obtain the existing `benchmark_reproduction` directory from the CPU84 setup package. Keep `shared_seed.zip`, `reproduction_manifest.json`, and `overrides/cpu_serial/` together. The seed must be exactly62,823,211 bytes with SHA256 `89c281267262bab336e3421ace9ccf41e4ec3fbdf1a42612e50dbdbd92bc62eb`. The reproduction manifest must be `e75dea5cbaaae870cf568266d95a61cc3fa28a288c4d39113e00aecc08a880c9`, and CPU benchmark manifest `5194b4442563947edc79af4f273dc67bc1b486b39e08d740352627d40c607f80`. These are dependencies, not absent duplicated assets.
2. Verify this addendum's manifest, [saved-field catalogue](SAVED_FIELD_CATALOGUE.json), [case-input catalogue](CASE_INPUT_CATALOGUE.json), and source/strict-review pins in [DEPENDENCY_MAP.json](DEPENDENCY_MAP.json). The offline restoration helper performs seed/member/input/field checks before creating anything. Its default only verifies. For example, from the addendum root: `python3 recipes/restore_completed_evidence.py --seed /absolute/path/benchmark_reproduction/shared_seed.zip`. No subprocess is used.
3. To materialize read-only historical evidence in a **new** directory, add `--restore-to /absolute/path/to/new_cpu_evidence`. The destination must be canonically disjoint from both the package and seed directory: neither a descendant nor an ancestor of either source. The helper rejects existing destinations and symlink, junction or reparse-point ancestors before resolving paths or creating anything. It extracts the seed's identical initial U/p and mesh into both roles, applies exact published CPU overrides followed by `case_inputs/{foundation14_control,native_cpu}`, copies canonical initial phi into each0.6 directory, then places all saved output fields at0.6001–0.6005. It never modifies the package or seed. The source Allrun is inert; no solver is launched.
4. The derived `offline_relocated_input_audit.json` changes only paths to the restored same-hash inputs and the preserved Root authorization. It is a relocation record for offline analysis, **not** new runtime permission. The original audit remains unchanged in `evidence/strict_runs/root_input_audit.json`. All exact underlying criteria and hashes remain visible.
5. Re-evaluate the original strict mechanical analyzer with `recipes/replay_completed_cpu_analysis.py --base /absolute/path/to/new_cpu_evidence --out /absolute/path/to/new_report.json`. Before importing included code, this adapter checks the base, package, explicit input paths and output for linked/reparse ancestors and checks canonical output containment. It repeats output checks before writing. It imports the byte-identical historical analyzer and helpers, relocates only their threshold/helper/cache paths, and uses the derived audit. It does not change numerical formulas, criteria, logs or fields. A replay with a different NumPy version can differ in last-bit reductions; the original version is recorded.

The original analysis and external Root gate are `evidence/strict_runs/f14_to_cpu_analysis.json` SHA256 `9514a88c2ac7fbfce110eae39cc7edc0c8d2614e7bc21c6d28150a294951190e` and `root_f14_to_cpu_external_gate.json` SHA256 `9d1a7729b4368eba60bb7f298836c5f1866dde3dd6e9ab31e4221359edd9cfa2`. All499 checks pass. Replayed mechanical observations do not replace true runtime/input/loader evidence and cannot qualify the failed GPU transient.

The extra `0.6/c29_initialU`, `c29_initialP` and `c29_initialPhi` files were startup audit observations with different headers/serialization. Their exact hashes and complete block-comparison results remain in the original startup receipts/reports; their large duplicate numeric payloads are not repeated. They are not inputs to the five-step solver or dependencies of the 499-check mechanical replay. Actual initial U/p and the canonical shared phi are available exactly as described above.
